# 목표 지출대 기반 장소 예산 랭킹 설계

## 배경

2026-07-27 실데이터 점검에서 예산 입력은 클라이언트부터 `recommendation_sessions`까지 정상 전달됐고, 가격 추정 400 수정 뒤에는 `places` 원장에도 정상 저장됐다. 그러나 현재 `budgetScoreFor`는 "스텝 예산 이하이면 모두 가점, 1.5배 초과면 감점"만 적용한다. 따라서 높은 예산을 입력해도 저렴한 장소가 같은 가점을 받아, 사용자가 입력한 예산대에 가까운 코스를 우선하지 못한다.

사용자는 예산을 **목표 지출대**로 정의했다. 즉, 예산은 단순한 최대 한도가 아니라 코스가 가급적 그 금액대에 가까워야 한다는 선호다.

## 목표와 비목표

### 목표

- 입력한 2인 총 예산을 코스 스텝 수로 나눈 1인·스텝별 목표 금액 근처의 알려진 가격 장소를 우선한다.
- 목표보다 지나치게 저렴한 장소와 지나치게 비싼 장소를 모두 감점하되, 비싼 쪽의 감점을 더 크게 둔다.
- 예산을 입력하지 않았거나 가격을 모르는 장소는 기존처럼 예산 점수 0으로 둔다. 가격 때문에 후보가 없어지는 하드 필터는 만들지 않는다.
- 신규 장소 가격은 현재처럼 추천 응답 뒤 백그라운드에서 축적한다. 요청 중 가격 AI 호출을 추가하지 않아 응답 지연과 호출 비용을 늘리지 않는다.

### 비목표

- 식사·카페·활동별 예산을 서로 다르게 배분하지 않는다. 이번 변경의 목표는 기존 균등 분할 앵커의 의미를 바로잡는 것이며, 카테고리별 배분은 별도 제품 결정이다.
- 총 코스 금액을 정확히 산출하거나 결제·메뉴 가격을 보장하지 않는다. 원장 가격은 장소의 1인 예상 범위다.
- 가격을 모르는 후보를 제거하거나, 추천 전에 후보별 가격을 AI로 동기 추정하지 않는다.

## 확정 규칙

`priceAnchorKRW(totalBudgetKRW, stepCount)`의 값을 `targetKRW`로 부른다. `PriceRange`의 `minKRW`/`maxKRW`가 다음 구간과 만나는지로 점수를 정한다. 범위가 한쪽만 있으면 존재하는 경계만 비교한다.

| 가격 범위와 `targetKRW`의 관계 | 예산 점수 | 의도 |
| --- | ---: | --- |
| 목표 구간 `0.75×target` ~ `1.25×target`과 겹침 | `+20` | 목표 지출대에 가장 가까움 |
| 목표 근처 구간 `0.55×target` ~ `1.50×target`과만 겹침 | `+4` | 합리적인 근접값 |
| 가격 범위 전체가 `0.55×target` 미만 | `-10` | 목표 대비 지나치게 저렴함 |
| 가격 범위 전체가 `1.50×target` 초과 | `-20` | 목표 대비 지나치게 비쌈 |
| 알려진 범위이나 위 비교가 불가능함 | `0` | 불완전한 가격 정보에 과도한 판단을 하지 않음 |
| 가격 미상 또는 예산 미입력 | `0` | 기존 후보 풀이 유지됨 |

목표 구간을 먼저 판정한다. 예를 들어 목표가 50,000원이고 예상 범위가 35,000~45,000원이면 목표 구간(37,500~62,500원)과 겹쳐 `+20`이다. 범위가 넓어 목표 구간을 포함하면, 불확실성을 이유로 저가·고가로 단정하지 않고 `+20`을 준다. 비싼 장소의 감점이 더 큰 것은 목표 지출대라도 실제 지출 부담을 막기 위해서다.

가격 점수는 기존 카테고리·직접 핀·필수 step intent·제외 조건·도보 제약보다 앞서지 않는다. 같은 제약을 만족하는 후보 사이에서 선택 순위를 바꾸는 소프트 점수다.

## 데이터 흐름

```text
1인 예산 입력
  → 클라이언트가 2인 총액으로 변환(totalBudgetKRW)
  → Edge가 스텝 수로 균등 분할(targetKRW)
  → places 원장에서 후보 가격 범위 조회
  → target budget score로 후보 랭킹
  → AI가 검증된 후보 ID만 선택
  → 선택 장소는 응답 후 백그라운드 원장 기록·가격 추정
```

따라서 이번 추천에서 가격이 없는 신규 후보는 중립이고, 해당 장소가 선택돼 축적된 다음 추천부터 목표 지출대 점수에 참여한다. 이 지연은 추천 응답 시간을 유지하는 의도적 경계다.

## 검증 기준

- 순수 단위 테스트가 목표 근처·지나치게 저렴함·지나치게 비쌈·가격 미상·예산 미입력을 각각 고정한다.
- 랭킹 테스트가 같은 카테고리·거리 후보에서 목표 근처 가격 후보를 최상위로 두는지 확인한다.
- 기존 교체 후보는 전체 예산을 스텝 수로 나눈 값만 전달한다는 회귀 테스트를 유지한다.
- 전체 Jest, `npm run validate` 통과 후 `recommend-date`와 `replacement-candidates`를 함께 재배포한다. 공유 랭킹 모듈 변경이므로 한 함수만 배포하지 않는다.
- 실데이터에서 서로 다른 예산 두 개로 같은 지역·동일 스텝 조합을 생성해 요청값, 선택 장소 가격, 추정 로그 성공 여부를 확인한다.
