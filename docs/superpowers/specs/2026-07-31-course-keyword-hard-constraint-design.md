# 코스 키워드 필수 조건 설계

## 배경

코스 스텝의 선호 키워드(기본 제안 칩과 직접 입력 모두)는 현재 `preferred` intent로 처리된다. 검색과 랭킹 가점은 받지만 최종 코스 조립은 비매칭 카테고리 후보로 완화할 수 있어, 사용자가 선택한 라멘·샐러드 등의 키워드가 결과에 반영되지 않을 수 있다.

## 결정

사용자가 코스 스텝에서 선택하거나 직접 입력한 키워드는 모두 해당 스텝의 **필수 조건**으로 처리한다. 기본 제안과 직접 입력의 의미를 구분하지 않는다.

## 동작

1. 키워드가 없는 스텝은 기존 카테고리·거리·예산·동선 기준으로 추천한다.
2. 키워드가 있는 스텝은 키워드 검색 결과 또는 장소명·검증 카테고리 근거로 해당 키워드를 충족한 후보만 선택할 수 있다.
3. 후보 풀에는 키워드와 무관한 장소가 함께 존재할 수 있지만, 키워드 스텝의 AI 선택과 결정론 폴백은 모두 매칭 후보로 제한한다.
4. 매칭 후보가 없거나 코스를 만들 수 없으면 일반 장소로 조용히 완화하지 않고 기존 `STEP_INTENT_UNSATISFIED` 오류를 반환한다. 클라이언트는 기존 조건 수정 안내를 표시한다.
5. 입력 키워드는 한 스텝당 하나라는 기존 계약을 유지한다. 키워드 복수 선택·키워드 제거 UX는 이번 범위가 아니다.

## 구현 경계

- `resolveStepIntents`: 태그에서 만든 intent의 `strength`를 `required`로 설정한다.
- `recommendation-course-selection`: 이미 `required` intent에 적용하는 후보 필터를 AI 선택 검증과 결정론 폴백에서 공통으로 사용한다.
- 검색·랭킹·카카오 검증 규칙은 바꾸지 않는다. 사전 미등재 키워드도 현재처럼 원문 키워드 검색 근거를 사용한다.
- API 계약, DB 스키마, 개인 키워드 저장 방식은 변경하지 않는다.

## 검증

- 기본 제안 키워드(라멘)가 비매칭 식당보다 우선이 아니라, 비매칭 식당을 아예 선택할 수 없음을 테스트한다.
- 직접 입력 키워드(샐러드)도 같은 필수 제약을 받음을 테스트한다.
- 매칭 후보가 없으면 `STEP_INTENT_UNSATISFIED`로 실패하며 일반 카테고리 후보로 완화되지 않음을 테스트한다.
- 관련 Jest 테스트와 `npm run validate`를 실행한다. 공유 Edge 모듈 변경이므로 `recommend-date`와 `replacement-candidates`를 함께 배포한다.
